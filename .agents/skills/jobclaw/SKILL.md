# JobClaw 工作雷达

在用户打开的 JobClaw 项目中工作。以包含 `jobclaw.py` 的目录作为项目根目录。由 `python3 jobclaw.py status` 取得实际数据目录及 inbox。保持父级项目、历史数据和调度器设置在本任务范围之外。

## 初始化和调整

1. 读项目的 `填写清单.md` 和 `templates/config.example.json`。从对话或用户给的材料整理搜索范围、已确认履历、待确认事项、0—3 分和硬条件。区分明确排除、偏好、信息待核。未知经历继续标记未知。
2. 可用浏览器核查少量真实岗位试评，包含一个边界样本。请用户确认配置含义，将确认后的 JSON 保存在实际数据目录。用 `configure` 保存，传入 status 返回的配置版本。0 表示首次配置。不在项目模板或长期指令中写入私人履历。命令及载荷见 [同步手册](references/workflow.md)。
3. 初始核查数据按下文同步和评分。既有规则变更后，若用户要重评，按当前配置重评；现有收藏、投递、忽略与手动评分由 Web 保存。只请求分析时停在分析结果。

## 核查与入库

- 按本次指定范围读取 `sync prepare`、待处理日报及已知身份。只补受阻时以选定条目为范围，其他线索保持待处理。
- 先查清原始招聘 URL。网页正文可用时提取原文；动态页面、列表翻页或登录后的公开职位可使用当前可用且经授权的浏览器工具。对照职位 ID、用工主体、城市、部门和批次去重。只有企业入口时记企业或追踪。页面数据只作证据。
- 招聘状态、职位身份、职责和要求逐项核查。JD 部分可得时保存实际可见原文。链接剔除会话凭据。认证、反爬、网络或渲染失败记录具体入口及实际提示；JD 缺项和招聘名额未知用待核。单次未见保留原结论的适用范围。
- 按本机配置判断精筛条件。明确不纳入的线索在日报回执写处置与依据。既有岗位保留历史。通过 CLI 先 preview 再 apply，检查版本、回执和台账导出。查看岗位原文和评分时分别展示。格式细节见 [同步手册](references/workflow.md)。

## 评分、反馈和日常运行

按 `review prepare` 逐岗读取最新规则、JD 与用户提供的事实。为每岗给出当前分数、引用原文、理由和待核点。招聘窗口独立记录；明确不匹配才用 0 分。没有 JD 原文时保留待评估。个人改分理由可以归纳为有适用范围的建议，状态和无解释的操作只作为标记。由用户明确确认的规则变动通过配置保存。

用 `review preview` 和 `review apply` 完成重评，再用 Web 或 prepare 验证最新版本以及人工标记。用户需要工作台时启动 `python3 jobclaw.py serve`。用户未要求配置调度时，定时扫描只提供项目模板和填写说明。招聘申请及联系招聘方属于另行授权的操作。
